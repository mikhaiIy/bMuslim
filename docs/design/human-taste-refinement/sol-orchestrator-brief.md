# SOL design-orchestrator brief

You are the clean-context SOL-high creative director for bMuslim, an Android-native devotional
timeline. Work from `docs/research/human-taste-refinement/research-lock.md` and inspect the existing
two-view concept images under `design/two-view/round-2/` and `design/two-view/round-3/`.

Do not design code. Produce a terse, executable visual direction and seven image-generation prompt
specifications for a controlled comparison. Preserve the existing living-almanac identity: deep
pine mineral atmosphere, warm paper, bone numerals, restrained saffron, matte tactility, circular
24-hour wheel, five prayer anchors, small crescent/sun cues. The result should feel quiet,
devotional, human-made, and Android-native—not luxury branding, dashboard chrome, or generic
Material cards.

The controlled comparison must cover:

1. A settled 05:59 overlap screen for each label hypothesis A, B, and C on the same regular device.
2. A direct-touch 05:59 screen for C, where contextual practice is pruned without hiding Subuh.
3. A 50% glance-to-detail transition using one bounds-safe overlay clock.
4. The same 50% transition using an exclusive clock-role handoff.
5. An adaptive maximum-type detail endpoint that genuinely reallocates header/aperture space.

For each prompt, specify exact visible copy, hierarchy, type-scale intent, pointer/leader behavior,
clock containment, wheel crop, detail-sheet state, and forbidden failure modes. Use cautious Malay
copy such as `Waktu Subuh · 05:59` and `Amalan berkaitan · Zikir pagi`; do not use copy implying an
iqamah or legal validity window. Make the primary fardhu readable in grayscale through placement,
size, and weight—not saffron alone. Keep contextual practice subordinate but recoverable.

Conclude with a provisional recommendation, implementation questions still requiring comparison,
and a one-paragraph design bible shared by all seven screens. Do not claim generated-image evidence
or select a final winner before the images exist.
